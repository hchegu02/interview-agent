## 版本三：十句话 / 一页附录版（**校招或正式投递重点项目用**）

> **Interview Agent — 基于自研 Graph 框架的分布式 AI 面试评估系统**
> 个人项目 | 2025.10 – 至今 | Go 1.25 · Gin · PostgreSQL+pgvector · Redis Streams · LLM/RAG
> 仓库：`github.com/your/interview-agent`（私有，可面试演示）

### 项目背景
求职者备战面试时缺乏 **针对岗位 JD 和个人简历的个性化训练**，市面工具多为通用题库或单轮问答。本项目构建从 JD/简历输入到模拟面试再到结构化复盘报告的完整训练闭环。

### 核心技术亮点

1. **自研轻量决策图框架** —— 不依赖字节 Eino 等开源框架，自研 ~500 行 Graph 引擎（`internal/graph/`），核心抽象为 `NodeFunc(ctx, *Session) error` 与纯函数 `Router`，通过 `ErrSuspended` 哨兵 + `Session.CurrentNode` 实现节点挂起 / Resume 恢复，支持单图内挂起任意节点等待外部输入。

2. **9 节点两层子图 DAG 编排** —— Setup 子图（parse_jd → parse_resume → gap_analyze → retrieve_rag）+ Agent loop 子图（pick_next ⇄ evaluate → critic → refine? → probe_ask/probe_eval+ → update_memory → reflection_check → loop or report），每个节点契约清晰、可独立测试。

3. **多实例分布式会话协调** —— 基于 Redis 实现 Session Lease（acquire/renew/release）+ Snapshot（save/load/delete），支持跨实例 Takeover：实例 A 宕机时实例 B 在本地 store miss 后从 Redis snapshot 恢复继续 answer；Lease 冲突通过 **HTTP 409 + Retry-After 客户端长重试** 配合 **服务端 3 次指数退避（25→50→100ms）+ 半量抖动短重试** 吸收瞬时切换。

4. **三层防护体系** —— 链路：`HTTP MaxInFlight → Service → Breaker → Limiter → Real LLM`。HTTP 入口背压用 buffered chan 非阻塞 try-acquire（只挂 `/start` `/answer` 不影响健康检查/流式接口），熔断器只统计可重试错误（`ErrTransient` + `DeadlineExceeded`，不计 `Canceled`/`Permanent`）半开期单 probe 探测，进程内 Limiter 等闸门时尊重 request context；熔断 open 时 `/readyz` 返回 200 degraded 避免 k8s 误踢 pod。

5. **显式降级与集中可观测** —— 所有降级路径必须显式写入 `WorkingMemory.DegradedReasons` 强类型表（key 使用稳定 component 名如 `pick`/`eval`/`rag`/`redis_snapshot`），最终报告自动汇总降级组件提示用户复测；区分"可降级"（Redis snapshot 失败不阻断）与"必须强一致"（Lease acquire/renew 失败必须阻断 = 多实例所有权边界）。

6. **RAG 多路融合检索** —— PG 端两阶段召回（vector candidates + tag candidates 并行），Go 端 `LinearFusion` 三路评分融合（vector / topic / difficulty），离线 `cmd/reindex` 重建 embedding 与在线服务解耦，启动时强校验 Embedding 维度与 `vector(N)` 一致。

7. **SSE 流式响应 + 断线回放** —— `GET /stream` 支持 snapshot + heartbeat 保活 + `Last-Event-ID` 历史事件回放；`InterviewEventHub` 双实现（内存 / Redis Streams 靠 `INTERVIEW_REDIS_URL` 切换），修复了 Subscribe→Publish 之间 readLoop 未进入 `XREAD $` 的 race（同步打开连接读取 stream 最新 ID 再返回）以及 Publish/Close 并发可能向已关闭 channel 发送的 race（锁内发送、Close 不交叉关通道）。

8. **完整工程化交付** —— Mock/Real 双模式（单测无网络、无 PG），SessionStore 接口三实现（内存/PG/Redis），双平台 smoke 脚本（`smoke.sh` + `smoke.ps1`），CLI demo 工具按 YAML 脚本驱动整图跑完整面试并输出 `run.json`（机器可读）+ `report.md`（人读），Docker Compose 一键起 PG+Redis，集成测试受 `INTEGRATION=1` 控制 CI 默认 skip。

### 关键工程取舍
- **为什么自研 Graph 而不用 Eino**：Eino 是 LLM 优先的框架，挂起恢复语义、纯函数 router 约束、错误分类等需求自研更易做强约束（架构规则写进 `CLAUDE.md` 长期可维护）。
- **为什么 Score = -1 而不是 nil**：Go 没有 nullable int，引入哨兵显式区分"答得很差(0)"与"评估失败(-1)"，所有统计逻辑必须先判 `< 0`。
- **为什么 readyz 在熔断 open 时返回 200 degraded**：熔断 open 时节点降级路径仍可答题，k8s 把 pod 拉出 service 反而损失可用容量。
- **为什么 WorkingMemory.Notes 演进成强类型字段**：弱类型 map 容易出 typo 且无编译期检查；已写 `MigrateLegacyState()` 兼容线上历史 session 快照。

### 数据与可验证产物
- 全量 `go test ./... -count=1` 通过；关键集成测试可在本机用 `INTEGRATION=1 INTERVIEW_POSTGRES_DSN=... INTERVIEW_REDIS_URL=...` 跑通
- 跨实例 Takeover、Redis Streams 事件总线、PG session store 三组集成测试均已 **真实数据库** 验证
- `make demo-mock` / `make demo-real` 端到端产出 `run.json` + `report.md`

适用：投金山云、字节、快手等中大厂校招或高质量实习，**这是你最完整的"门面"**。
