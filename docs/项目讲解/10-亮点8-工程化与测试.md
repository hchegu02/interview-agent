## 一、三套部署模式

### 1.1 模式对照表

| 维度 | 模式 A：单 binary | 模式 B：单实例 + Docker | 模式 C：多实例 + k8s |
|---|---|---|---|
| **依赖** | 无 | PG + Redis | PG + Redis + k8s |
| **启动** | `go run ./cmd/server` | `make docker-up && go run ./cmd/server` | k8s deploy + ConfigMap |
| **LLM** | Mock | Real（dashscope）| Real |
| **Session 存储** | 内存 | PG state_json | PG state_json |
| **跨实例协调** | 无 | 无 | Redis Lease + Snapshot |
| **SSE Hub** | 内存 | 内存 | Redis Streams |
| **题库检索** | fallback JSON | pgvector | pgvector |
| **用途** | 单测 / 演示 | 个人开发 / 小生产 | 真正多实例 |

**关键设计：用同一份代码支持三种模式**——通过配置 + 接口抽象实现。

### 1.2 配置驱动选择

```yaml
# config/config.yaml
mode: real            # mock | real
http:
  addr: ":8080"
  max_in_flight: 32   # 0 = 关闭背压

llm:
  provider: openai_compatible
  base_url: ${LLM_BASE_URL}              # ENV 必填
  api_key: ${LLM_API_KEY}                # ENV 必填，不允许进 YAML
  model: qwen-turbo
  max_concurrency: 4
  breaker:
    failure_threshold: 5
    open_duration: 30s

embedding:
  provider: dashscope
  api_key: ${EMBEDDING_API_KEY}
  model: text-embedding-v3
  dimension: 1024

postgres:
  dsn: ${PG_DSN}                         # 空值 = 用 fallback 题库
  max_conns: 10

redis:
  url: ${REDIS_URL}                      # 空值 = 单实例 + 内存 hub
```

### 1.3 启动校验（fail-fast）

```go
// internal/config/validate.go
func (c *Config) Validate() error {
    if c.Mode == "real" {
        if c.LLM.APIKey == "" {
            return fmt.Errorf("LLM.api_key required in real mode")
        }
        if c.LLM.MaxConcurrency <= 0 {
            return fmt.Errorf("LLM.max_concurrency must be > 0")
        }
        if c.LLM.Breaker.FailureThreshold <= 0 {
            return fmt.Errorf("LLM.breaker.failure_threshold must be > 0 in real mode")
        }
    }

    if c.HTTP.MaxInFlight < 0 {
        return fmt.Errorf("HTTP.max_in_flight cannot be negative")
    }

    // 多实例模式要求 Redis 配置
    if c.MultiInstance && c.Redis.URL == "" {
        return fmt.Errorf("redis.url required when multi_instance=true")
    }

    return nil
}
```

**为什么启动校验**：

> **配置错应该在 server boot 时 fail**，而不是用户访问到第 17 个节点才报"api_key empty"。

```bash
#!/bin/bash
set -e

BASE_URL="http://localhost:8080"
SESSION_ID="smoke-$(date +%s)"

# 1. 健康检查
curl -fsS "$BASE_URL/healthz" | grep -q '"status":"ok"' || exit 1

# 2. start
curl -fsS -X POST "$BASE_URL/api/interview/start" \
    -H 'Content-Type: application/json' \
    -d "{\"session_id\": \"$SESSION_ID\", \"jd_text\": \"...\", \"resume_text\": \"...\"}" \
    | tee /tmp/start.json

# 3. answer
curl -fsS -X POST "$BASE_URL/api/interview/answer" \
    -H 'Content-Type: application/json' \
    -d "{\"session_id\": \"$SESSION_ID\", \"answer\": \"...\"}" \
    | tee /tmp/answer.json

# 4. 等结束
# ... loop until status == completed ...

# 5. 拿 report
curl -fsS "$BASE_URL/api/interview/sessions/$SESSION_ID" | tee /tmp/final.json

echo "✅ smoke passed"
```

## 四、可执行的工程纪律（CLAUDE.md / HANDOFF.md）

### 4.1 CLAUDE.md（架构规则）

```markdown
# 这是给 AI / 接手人看的项目纪律

## 必须做：
- Router 必须是纯函数，禁止副作用
- 所有 LLM 失败显式降级 + 写 DegradedReasons
- 节点签名必须是 NodeFunc(ctx, *Session) error
- Lease/Snapshot 失败按"边界"判断阻断 vs 降级

## 不要做：
- 不要在节点里静默吞掉 LLM 错误
- 不要在 Router 里写 sess.X = Y
- 不要在 Migration 里反向写老字段
- 不要在 master 直接合并未测试代码

## 命令速查：
make test          # 单测
make lint          # golangci-lint
make smoke         # 端到端
make demo-mock     # CLI demo（mock）
```

**为什么这种文档有价值**：

- **新人 onboard 时间从 1 周缩短到 0.5 天**
- AI Agent（如 Claude Code）可以读这份文档，自动遵守规则
- **架构腐化的最大原因是规则没写下来**，写下来就能强制执行

- 比"每次写 ALTER TABLE 改在原 SQL 文件"清晰得多

## 八、配置三层加载

```go
// internal/config/loader.go
func Load(yamlPath string) (*Config, error) {
    // 1. 加载 YAML 默认值
    cfg, err := loadYAML(yamlPath)
    if err != nil {
        return nil, fmt.Errorf("load yaml: %w", err)
    }

    // 2. ENV 覆盖（${VAR} 占位符替换）
    if err := applyEnvOverrides(cfg); err != nil {
        return nil, fmt.Errorf("apply env: %w", err)
    }

    // 3. 强制校验
    if err := cfg.Validate(); err != nil {
        return nil, fmt.Errorf("validate: %w", err)
    }

    return cfg, nil
}
```

### 8.1 API key 强制走 ENV（安全纪律）

```go
// internal/config/secrets.go
func (c *Config) loadSecretsFromEnv() error {
    if c.Mode == "real" {
        if c.LLM.APIKey == "" {
            c.LLM.APIKey = os.Getenv("LLM_API_KEY")
        }
        if c.Embedding.APIKey == "" {
            c.Embedding.APIKey = os.Getenv("EMBEDDING_API_KEY")
        }

        // ✅ 严格规则：API key 必须在 ENV，不允许写在 YAML
        if strings.HasPrefix(c.LLM.APIKey, "sk-") && yamlContainsAPIKey(c.LLM.APIKey) {
            return fmt.Errorf("LLM.api_key should be in ENV, not YAML (security)")
        }
    }
    return nil
}
```

**为什么强制走 ENV**：

- YAML 容易被 commit 进 Git（即使 `.gitignore` 也容易出错）
- ENV 是 12-factor app 标准
- k8s Secret / Vault 都直接映射 ENV，无缝衔接

## 十、可能的追问与回答

### Q：为什么不用 Helm / Kustomize？

**A**：当前项目还是单仓库 + 单 binary，**k8s 部署是 TODO**。已经写在 HANDOFF.md，但还没必要立即做。**过早 k8s化 = 过度工程**。

### Q：你的 CI 在哪？

**A**：当前项目没正式 CI（个人项目），但所有 hook 都已经准备好：`make test / lint / smoke / integration`。需要时 5 分钟加 `.github/workflows/ci.yml`。

### Q：怎么保证 demo 永远能跑？

**A**：
- `make demo-mock` 跑在每次 PR（CI 加进去就行）
- 节点改动会让 demo 输出变化，**run.json diff 直接看出问题**
- 这是端到端回归测试的轻量化版本

### Q：项目代码量多大？

**A**：
- `internal/` ~5000 行 Go（业务逻辑）
- `cmd/` ~800 行（server + demo + reindex + migrate）
- 测试 ~6000 行（含集成测试）
- 文档 ~3000 行 Markdown
- **代码 / 测试 / 文档 比例约 1 : 1.2 : 0.6**，重测试 + 重文档

### Q：怎么衡量项目"完成"？

**A**：
- ✅ 9 个核心节点全部 work + 测试覆盖
- ✅ 三种部署模式都能跑通
- ✅ `make demo-real` 能用真 LLM 生成完整报告
- ✅ 多实例 takeover 集成测试通过
- ✅ 所有架构亮点都有独立文档可讲

### Q：你这套工程化能复用到其他项目吗？

**A**：可以，关键复用点：

- `CLAUDE.md` / `HANDOFF.md` 写法
- Makefile 三层命令分层（dev / test / ops）
- 单测 / 集成 / smoke 三层测试金字塔
- 配置三层加载（YAML + ENV + Validate）
- `cmd/demo` 这种"永远能跑的端到端"

> **这些是工程素养的固定打法，跟具体业务无关**。
