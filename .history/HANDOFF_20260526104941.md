# Interview Agent — 项目交接 HANDOFF

> 交接快照。长期规则见 `CLAUDE.md`，本文件只描述当前进度、注意事项和下一步。

## 1. 项目目标

基于决策图编排框架的智能面试评估系统。面向 Go 后端岗位，核心能力：

- 自适应选题：`pick_next` 结合 `GapStrategy` / `SkillCoverage`
- 动态追问：`critic` 判信号后进入 `probe_ask` / `probe_eval` 循环
- Critic-Refine：对初评结果做二次反思和修正
- WorkingMemory：跨轮维护已确认技能、薄弱技能、覆盖度和预算
- Reflection：每轮结算后决定继续、补漏或结束
- Report：本地聚合生成结构化复盘报告
- Mock / Real 双模式：LLM 与 Embedder 都可切换

- Redis hub 使用标准库 RESP 实现，没有引入新的 go.mod 依赖；当前测试覆盖 URL 解析、RESP 编码/解析和 stream event 解码。
- Redis hub 已有轻量 stats：记录 publish error 数、last publish error 和 dropped events；publish 失败不阻断 interview 主流程。
- Redis hub 支持 ACL 用户名 URL：`redis://username:password@localhost:6379/0` 会使用 `AUTH username password`；旧的 `redis://:password@...` 仍使用 `AUTH password`。
- 已新增 Redis Streams 集成测试 `TestRedisInterviewEventHub_IntegrationPublishSubscribe`，受 `INTEGRATION=1` 控制；运行命令：`INTERVIEW_REDIS_URL=redis://localhost:6379/0 INTEGRATION=1 go test ./internal/httpapi -run TestRedisInterviewEventHub_IntegrationPublishSubscribe -count=1 -v`。

- 本轮真实验证：Redis Streams 集成测试已连 `redis://localhost:6379/0` 通过；Redis + SSE 服务级 smoke 已通过；PG session store integration 和 PG smoke 已通过。
- Redis session coordinator 已接入 `InterviewService` 主流程：设置 `INTERVIEW_REDIS_URL` 后，`start` 会 acquire lease 并写 snapshot；`get/answer` 在本地 store miss 时会从 Redis snapshot 恢复；`answer` 会 renew lease，若租约已过期则尝试 acquire 空租约，成功后写 snapshot；会话 completed 后释放 lease。
- Redis snapshot 写入失败不再打断 start/answer 主流程；会写 `WorkingMemory.DegradedReasons["redis_snapshot"]` 并回存 primary store。Redis lease acquire / renew 失败仍会阻断，因为它是多实例所有权边界。
- Redis 基础 takeover 已有真实集成测试覆盖：实例 A start 后 lease 过期，实例 B 本地无 session 时可从 Redis snapshot 恢复并完成 answer。
- Redis lease 冲突会返回 HTTP 409，并带 `Retry-After: 1` 和 JSON `retry_after_seconds: 1`；服务端在 `acquireSessionLease` 内做有界短重试（默认 3 次，25→50→100ms 指数退避 + 半量抖动，总耗时上限 250ms）以吸收 lease 切换瞬时冲突。重试用尽后仍翻 `ErrSessionLeaseConflict`，客户端继续按 `Retry-After` 做长重试。真错误（coordinator 返回 non-nil err）立刻冒泡，不重试。
- Redis session coordinator 集成测试命令：`INTERVIEW_REDIS_URL=redis://localhost:6379/0 INTEGRATION=1 go test ./internal/httpapi -run TestRedisSessionCoordinator -count=1 -v`。
- Service + Redis coordinator snapshot 集成测试命令：`INTERVIEW_REDIS_URL=redis://localhost:6379/0 INTEGRATION=1 go test ./internal/httpapi -run TestIntegration_InterviewService_RedisCoordinatorSnapshots -count=1 -v`。
- 基础 takeover 集成测试命令：`INTERVIEW_REDIS_URL=redis://localhost:6379/0 INTEGRATION=1 go test ./internal/httpapi -run TestIntegration_InterviewService_TakeoverFromRedisSnapshot -count=1 -v`。
- Real LLM 模式已接进程内并发 limiter：`llm.max_concurrency` 默认 4；等待 limiter 时尊重 request context，超时不会进入真实 LLM 调用。
- Real LLM 模式已加熔断器 `BreakingChatModel`，链路 `real → limited → breaker`（breaker 在最外层避免抢 limiter 槽位）。`llm.breaker_failure_threshold` 默认 5，`llm.breaker_open_duration` 默认 30s；只统计 `ErrTransient` 和 `context.DeadlineExceeded`，`ErrPermanent` / `ErrSchemaInvalid` / `context.Canceled` 不计入。open 时直接返回新哨兵 `ErrBreakerOpen`，不 wrap `ErrTransient`，避免上游误重试；半开期只允许 1 个 probe。
- `/readyz` 在 breaker 处于 `open` 时返回 200 + `{"status":"degraded","llm_breaker":"open"}`（不返 503）；节点降级路径仍可答题，k8s 不应把 pod 拉出 service。
- HTTP 入口背压：`MaxInFlightMiddleware` 用 buffered chan 做非阻塞 try-acquire；只挂在 `/api/interview/start` 和 `/api/interview/answer` 上，`/healthz`、`/readyz`、`/api/interview/stream`、`/api/interview/sessions` 不受影响。超限返回 503 + `Retry-After: 1` + JSON `retry_after_seconds: 1`，与 lease 冲突的 409 协议保持一致。`server.max_in_flight` 默认 200，<= 0 时 middleware 退化为 no-op。
- `InterviewService` 现在带内存事件总线，`graph.Callback` 会把节点 start/end/error 事件发到同一条流里。
- `internal/llm/recording.go`：新增 `RecordingChatModel` 装饰器（必须放在 BreakingChatModel 外层，记录 `ErrBreakerOpen` / `context.Canceled` 也算分类），导出 `CallRecord` 与 `ClassifyChatErr` 给 demo / observability 共用。

- 真实 LLM demo 流程已搭好（`cmd/demo` + `make demo-real`），但仍需操作者本地配置 `INTERVIEW_LLM_API_KEY` 跑一遍并人工评估 `run.json` / `report.md`；尚无跨多次运行的 prompt regression diff。

- README 已修正为自研 Graph，但设计文档里可能仍有 Eino/阶段旧描述。
- 当前环境多次出现 Windows sandbox `CreateProcessAsUserW failed: 1920`，导致 `gofmt`、`git status`、`go build`、`sh -n` 偶发无法执行；`go test ./... -count=1` 已通过。

## 9. 隐藏假设 / 临时方案

- `Score = -1` 表示评估失败，和 `Score = 0` 严格区分。
- probe loop 通过 `probe_eval` 改写 `CriticResult.HasProbeSignal` 实现。
- reflect 复用 `pick_next` 造环，补漏 topic 存在 `WorkingMemory.ReflectTopic`，由 `pick_next` 消费并清空；兼容消费旧 `Notes["reflect_topic"]`。
- `AvgScore` 用增量公式，计数存在 `WorkingMemory.ScoredRounds`；降级轮次存在 `WorkingMemory.DegradedRounds`。
- `SkillCategory` 优先于 `Tags` 做覆盖度聚合。
- `fallbackRetriever` 只用于未配置 PG DSN 时触发 RAG fallback，不是长期检索实现。
